# DCCCcore 4.6.3-alpha / dcccpy 0.3.0a7

This compatibility prerelease supersedes `4.6.2-alpha` / `dcccpy 0.3.0a6`.
It restores the historical FDG behavior of `adni-pet-core` and introduces
`scan-pet-core` as a separate opt-in interface.

| Interface | FDG intensity strategy |
| --- | --- |
| `adni-pet-core --tracer fdg` | Restored ADNI iterative global-mean normalization |
| `scan-pet-core --tracer fdg` | Highest ceil(N/2) intensities in a combined pons/vermis reference |

The iterative algorithm is restored from the original implementation.
SCAN uses the previously documented Clinica eroded pons + AAL2 vermis atlas
approximation. Registration, rigid output grid, motion correction, export
levels and defacing share the existing pipeline. SCAN currently requires FDG
and uses `_SCAN_style.nii` for batch Level 3 output.

```python
import dcccpy

dcccpy.adni_pet_core('fdg.nii.gz', 'adni_fdg.nii.gz', tracer='fdg')
dcccpy.scan_pet_core('fdg.nii.gz', 'scan_fdg.nii.gz', tracer='fdg')
```

Versions: core/tag `4.6.3-alpha` / `v4.6.3-alpha`, wrapper `0.3.0a7`,
and all four runtime packages `0.2.0a6`. Runtime packages are published before
the wrapper and pin this exact core version.

```sh
pip install --pre 'dcccpy[runtime]==0.3.0a7'
```

The prior `4.6.2-alpha` GitHub Release will be removed after this release's
publication and installation verification. PyPI cannot replace uploaded
filenames, even after deletion; old `dcccpy 0.3.0a6` and runtime `0.2.0a5`
versions must be retired separately through the PyPI management website.
The upload API token cannot perform that management operation.

Validation before release: Docker C++ build; 2 C++ numerical tests;
43 CLI/dynamic/help/asset tests; 58 Python package tests (one optional
TestPyPI case skipped). The new release requires its own cross-platform
Actions and public installation checks.
