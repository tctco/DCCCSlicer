# Compatibility release 4.6.3-alpha and retirement of 4.6.2-alpha

User authorized replacing the incompatible GitHub/PyPI release with the
ADNI/SCAN split. PyPI forbids filename reuse after deletion, so publish new
versions: core 4.6.3-alpha, wrapper 0.3.0a7, four runtime packages 0.2.0a6.

- Synchronize all core, wrapper, runtime, vendor and dependency versions.
- Validate versions and package tests, Docker build, both FDG interfaces and
  wrapper distribution checks before publishing the dev commit/tag.
- Build the complete GitHub release matrix from the new tag.
- Local systemd inspection every 30 minutes verifies the exact build commit,
  prerelease inventory and archive checksums. It builds slim runtime wheels
  from the release archives, validates contents/platform/size, and tests the
  local Linux wheel before publishing all runtimes then the wrapper.
- Independently install the published extras with downloads disabled, verify
  core/runtime versions and both ADNI/SCAN command interfaces, then delete
  only the superseded v4.6.2-alpha GitHub Release. Retain its source tag.
- PyPI release deletion/yanking requires a logged-in management website session;
  the supplied upload token cannot perform this action. Manual retirement is
  required for dcccpy 0.3.0a6 and four runtime versions 0.2.0a5. Do not claim
  those versions have been deleted or yanked without checking public metadata.

The old GitHub release is retained until the replacement passes installation
verification. Do not move/reuse the old tag or overwrite old PyPI filenames.
