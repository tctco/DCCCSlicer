# DCCC Seg Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline, as authorized by the user's instruction to begin implementation. Track task completion here.

**Goal:** Deliver native `DCCCcore seg`, `dcccpy.seg()` and a Slicer segmentation entry point.

**Architecture:** ITK geometry and preprocessing, ONNX Runtime patch inference, metadata-driven label adapters. Python nnU-Net is the Docker parity oracle, not a production dependency.

**Tech Stack:** C++17, ITK 5.3, ONNX Runtime 1.18, nlohmann_json, Python, Slicer/Qt.

**Spec:** `docs/superpowers/specs/2026-10-22-dccc-seg-design.md`

## Global Constraints

- Work on synchronized `feat/adni-pet-deface`, version `4.5.1-alpha`.
- Compile and execute tests only in Docker; preserve untracked user files.
- Exactly two rigid predictions; default TTA, step 0.5, native-space categorical output.
- No push or release; no Python neural-network dependency in production.

## Review Focus

- Oblique RAS/LPS/native restoration and parent transforms.
- Float16 reference accumulation and Gaussian edge weights affect argmax parity.
- Existing output targets, partial failures, 4-D and nonfinite input.
- Bundle metadata disagreement and missing installed model assets.
- Slicer scene access and busy UI during long CPU inference.
